# Comparables: how other field solvers expose mesh, solve, the solution, method choice and reuse

31 October 2026. Read-only. Every claim below comes from a page fetched today (URL given) or from a file line (`path:line`). Where a page could not be opened, the claim is marked unverified. No timing was run.

## The conclusion first

1. **Everyone separates "discretize" from "solve", and the discretization is an object the user holds and can inspect.** NGSolve `Mesh` + `H1(mesh, order=2)`, scikit-fem `Mesh` + `Basis(mesh, element)`, FEniCSx `mesh` + `functionspace`, bempp `grid` + `function_space`, SimPEG `mesh` + `survey` inside a `simulation`, Radia subdivided objects in containers, MagTense `Tiles`. The plan's optional `mesh()` step has priors everywhere. None of them records "which method made the mesh": the method *is* the object's type (an `HCurl` space, a `"DP", 0` space, a `Tiles` set).
2. **The kept factorization is an object in the user's hands, never a hidden store keyed on inputs.** NGSolve `inv = a.mat.Inverse(...)` applied as `inv * r`; scipy `splu(A)`, `factorized(A)`, `lu_factor`/`lu_solve`; pymatsolver `Ainv = Solver(A); x = Ainv * b`; FEniCSx a KSP with `setOperators(A)` set once; Radia an interaction-matrix handle from `radRlxPre`; MagTense a demag tensor returned and passed back in. No library read today keeps a global cache of factorizations keyed by a fingerprint. This backs the 31 October reversal of #132.
3. **Where a library caches, it caches on the object that owns the data and clears it on the setters that change the matrix.** bempp's operator caches its assembled weak form (`if not self._cached`); SimPEG lists `_delete_on_model_update` and calls `Ainv.clean()` before refactoring; FEniCSx's `bcs` setter "rebuilds the cached dof markers"; NGSolve's `Preconditioner` "is updated" whenever the `BilinearForm` is re-assembled. A mesh object that holds its factorization and a fingerprint is this pattern.
4. **Two shapes of solution exist, and the better libraries offer both:** a field object evaluated later at points (NGSolve `GridFunction`, FEniCSx `Function`, SimPEG `Fields`, bempp `GridFunction` plus potential operators, Radia's objects plus `radFld`), and arrays at observers named at solve time (MagTense `run_simulation(tiles, pts)`, SimPEG `dpred(m, f)`). SimPEG's `dpred(m, f=f)` reuses the fields object "without recalculating the fields". MR already has both shapes: `FemSolution.getB(observers)` and the `Collection` copies.
5. **Automatic choices exist only at the linear-algebra level, and the good ones say what they chose.** SimPEG picks its default solver by what is installed (Pardiso, then Mumps, then SuperLU) and logs "Setting the default solver ..."; it warns when a user picks the slow one. MR's `apply_demag(solver="auto")` logs "solver='auto' chose {solver}: FFT covers {share:.0%} of the interactions". scipy's `spsolve` switches to UMFPACK silently when installed; bempp's `"default_nonlocal"` assembler is silently dense. **No library read today picks a discretization method (FEM against BEM against moments) by itself.** The plan's `"auto"` between face charge and cells has no prior; if kept, the prior for its form is "log the choice and why, with a named override".
6. **Sweeps are "many right-hand sides on one factorization", done by the user or as RHS columns; nobody has a "path".** SimPEG solves all sources at once with `Ainv * RHS` (one column per source); pymatsolver takes "a single or multiple right hand sides"; NGSolve, scikit-fem and FEniCSx reuse the inverse in a time loop written by the user; FEMM re-solves every position (16 positions, about 40 s in 2003). The narrow form of paths is this same primitive with magpylib's path syntax; memory modes are exposed as knobs (SimPEG `store_sensitivities`: `'ram'`, `'disk'`, `'forward_only'`), not hidden.
7. **Convergence and accuracy are the user's to check, but the solution carries the numbers.** FEniCSx: "The user is responsible for asserting convergence of the KSP solver". pymatsolver can check `A x = b` and raise. Radia stops on a precision `prec` or `maxiter` and returns the last change in magnetization. MR's `FemSolution` carries `ndof`, `seconds`, `moment`; `face_charge_info` carries `unknowns`, `level`, `rounds`, `seconds`. Alex's "how do I even know it is accurate" has a prior answer: a solution object that reports residual, size and what it took.

## Per library

### Radia (ESRF, boundary-integral magnetostatics)

Sources: reference guide https://www.esrf.fr/Accelerators/Groups/InsertionDevices/Software/Radia/Documentation/ReferenceGuide (fetched, 83,409 characters, 58 functions), introduction https://www.esrf.fr/home/Accelerators/instrumentation--equipment/Software/Radia/Documentation/Introduction.html, Python examples https://raw.githubusercontent.com/ochubar/Radia/master/env/radia_python/RADIA_Example01.py, `.../RADIA_Example02.py`, `.../RADIA_Example05.py`.

- Nouns. Objects are integer handles: `radObjRecMag[{x,y,z},{wx,wy,wz},{mx,my,mz}]` "Creates a magnetized rectangular block ... Returns an integer reference"; `radObjCnt[{obj1,...}]` makes a container; `radObjDivMag[obj,{k1,k2,k3}]` subdivides and "a container actually appears in place of the object obj"; `radMatLin[{ksipar,ksiper}, mr]` makes a linear material, `radMatApl[obj, mat]` applies it. The mesh is the subdivision of the bodies themselves: "The method used in Radia belongs to the category of boundary Integral Methods" and it avoids meshing the empty space (introduction).
- Solve. "building a large matrix in memory which represents mutual interactions between the objects"; "The final magnetization in each small object is obtained iteratively ... by a sequence of multiplications of the Interaction Matrix by instant magnetizations vector. We call this a Relaxation procedure" (introduction). Reference guide: `radRlxPre[obj, srcobj:0]` "Builds an interaction matrix for the object referenced by obj, treating the object srcobj as an additional external field source ... Returns an integer reference"; `radRlxAuto[intrc, prec, maxiter, meth:3]` "Executes an automatic relaxation procedure" that stops when the change in magnetization falls below `prec` or after `maxiter`; `radRlxMan[intrc, meth, iternum, rlxpar]` runs a set number of iterations and returns the final change in magnetization and field. Python: `res=rad.Solve(t,0.0001,1500)` then `b0=rad.Fld(t,'Bz',[0,0,0])` (Example05). The relaxation method `meth` (0 to 4) is the caller's choice, default 3; nothing automatic.
- Solution. Nothing new is returned: the objects' magnetization is updated in place; `radObjM[obj]` "Returns the center coordinates and magnetization of each magnetized object"; the field is read anywhere afterwards, `radFld[obj, fid, {x,y,z}]` and `radFldLst` for many points, "the magnetic field and field integrals can be computed anywhere in space" (introduction).
- Reuse. The interaction matrix is a handle (`intrc`) that `radRlxAuto`/`radRlxMan` take, so it can be relaxed again; the external sources named in `radRlxPre` "will not change their parameters during the relaxation". Memory: "the memory required scales proportionally to the square of the number of elements", called the essential drawback (introduction). `radFldCmpPrc` "only concerns direct field computation methods and has no effect on the accuracy of relaxation procedure": field-evaluation accuracy and solve accuracy are separate settings.
- Sweeps. None built in; Example05 solves twice for two segmentations; Example02 evaluates `rad.Fld(g, 'bz', [[...] for iy in range(ny)])` on a list of points.
- Unverified: `radSolve[obj,prec,maxiter,meth]` is not on the ESRF page; a search snippet of the ftp mirror (http://ftp.esrf.eu/.../ReferenceGuideMath/ReferenceGuide.html, unreachable from here over HTTP and HTTPS) describes it as building the interaction matrix and relaxing in one call. `radRlxUpdSrc` was not found anywhere.

### MagTense (DTU, demagnetization-tensor method of moments)

Source: https://raw.githubusercontent.com/cmt-dtu-energy/MagTense/master/python/src/magtense/magstatics.py.

- Nouns. `Tiles` ("Input to Fortran derived type MagTile") with `M`, `M_rem`, `mu_r_ea`, `mu_r_oa`, `tile_type` ("1 = cylinder, 2 = prism, 3 = circ_piece, ..."), `magnet_type` ("1 = hard magnet, 2 = soft magnet, 3 = soft + constant mu_r"), `offset`, `rot`.
- Solve and solution. `run_simulation(tiles, pts, max_error=1e-5, max_it=500, T=300.0, mu_r=20) -> tuple[Tiles, np.ndarray]`: "Run magnetostatic simulation to calculate the demagnetizing field strength", returns "Updated tiles" and "Demagnetizing field strength in evaluation points". Observers are named at solve time. `iterate_magnetization(tiles, ...) -> Tiles` "Iterate through tiles to determine their influence on each other".
- Reuse. `get_demag_tensor(tiles, pts)` returns the tensor; `get_H_field(tiles, pts, demag_tensor=None)` takes "Optional precalculated demagnetization tensor". Reuse is the user holding a matrix and passing it back.
- Method choice: none. Sweeps: none built in.

### NGSolve (finite elements; what MR's `[fem]` extra uses)

Sources: https://docu.ngsolve.org/latest/i-tutorials/unit-1.1-poisson/poisson.html, https://docu.ngsolve.org/latest/i-tutorials/unit-1.3-dirichlet/dirichlet.html, https://docu.ngsolve.org/latest/i-tutorials/unit-1.4-staticcond/staticcond.html, https://docu.ngsolve.org/latest/i-tutorials/unit-2.1.1-preconditioners/preconditioner.html, https://docu.ngsolve.org/latest/i-tutorials/unit-2.4-Maxwell/Maxwell.html, https://docu.ngsolve.org/latest/i-tutorials/unit-3.1-parabolic/parabolic.html.

- Nouns. `mesh = Mesh(unit_square.GenerateMesh(maxh=0.2))`, `mesh.nv, mesh.ne`; `fes = H1(mesh, order=2, dirichlet="bottom|right")`, `fes.ndof` "number of unknowns" (129 in the example); `u, v = fes.TnT()`; `a = BilinearForm(fes); a += grad(u)*grad(v)*dx; a.Assemble()`; `f = LinearForm(fes)`; `gfu = GridFunction(fes)` which "represent functions in the finite element space" and holds the coefficient vector. Mesh settings (`maxh`) sit on the mesh; the order sits on the space; the physics sits on the forms.
- Solve. `gfu.vec.data = a.mat.Inverse(freedofs=fes.FreeDofs()) * f.vec`; "only the remaining 'free' degrees of freedom should participate in the linear solve". Iterative: `c = Preconditioner(a, "bddc")` then `solvers.CG(sol=gfu.vec, rhs=f.vec, mat=a.mat, pre=c.mat, printrates=True)` (Maxwell unit: a bar magnet, `HCurl(mesh, order=3, dirichlet="outer", nograds=True)`, `mur = mesh.MaterialCF({"magnet": 1000}, default=1)`, `ndof = 33832`, "we regularize by adding a very small L2 term", 75 CG iterations, B drawn as `curl(gfu)`).
- Method choice. The user picks: preconditioner types "local", "direct" ("Direct solvers using sparse factorization"), "multigrid", "h1amg", "bddc". Nothing automatic.
- Reuse. The inverse is an object: `invS = a.mat.Inverse(freedofs=fes.FreeDofs(coupling=True))`, `invA = ext @ invS @ extT + a.inner_solve`, `u.vec.data = invA * f.vec` (static condensation). Time stepping: `mstar.AsVector().data = m.mat.AsVector() + dt * a.mat.AsVector()`, `invmstar = mstar.Inverse(freedofs=fes.FreeDofs())` built once, then in the loop `res = dt * f.vec - dt * a.mat * gfu.vec; gfu.vec.data += invmstar * res`. "The Preconditioner registers itself to the BilinearForm. Whenever the BilinearForm is re-assembled, the Preconditioner is updated as well."
- Sweeps: the user's loop over the kept inverse (parabolic unit).
- In MR, `FemSolution` evaluates NGSolve coefficient functions at located mesh points (`model.locate`, `cf(mp)`): `src/magpylib_material_response/fem/_solve.py:376-402`.

### scikit-fem (finite element assembly on NumPy/SciPy)

Sources: https://scikit-fem.readthedocs.io/en/latest/gettingstarted.html, https://scikit-fem.readthedocs.io/en/latest/api.html, https://raw.githubusercontent.com/kinnala/scikit-fem/master/skfem/utils.py, https://raw.githubusercontent.com/kinnala/scikit-fem/master/docs/examples/ex19.py.

- Nouns. `mesh = fem.MeshTri().refined(3)`; `Vh = fem.Basis(mesh, fem.ElementTriP1())` ("CellBasis object is a combination of Mesh and Element"); forms as decorated functions `@fem.BilinearForm def a(u, v, _)`; `A = a.assemble(Vh); b = l.assemble(Vh)`; `D = Vh.get_dofs()`; `x = fem.solve(*fem.condense(A, b, D=D))`. `condense` "Eliminate degrees-of-freedom from a linear system"; `enforce` is "An alternative to condense()".
- Solution: a plain coefficient array; read back with `Vh.interpolate(x)` (the error functional in the walk-through).
- Method choice. `solve(A, b, x=None, I=None, solver=None, **kwargs)`: "Choose one of the following solvers: skfem.utils.solver_direct_scipy() (default)", `solver_iter_pcg`, `solver_iter_krylov`. `solver_direct_scipy` is "The default linear solver of SciPy" and its body calls `spl.spsolve(A, b, **kwargs)`: a fresh solve each call, no factorization kept anywhere in the library.
- Reuse. Left to the user, shown in ex19: "a linear algebraic problem at each time with the same matrix but changing right-hand side. This motivates factoring the matrix; e.g. with scipy.sparse.linalg.splu": `backsolve = splu(A.T).solve`, then `t, u = t + dt, backsolve(B @ u)`.

### SimPEG (geophysical simulations; the closest "solver object" prior)

Sources: https://docs.simpeg.xyz/latest/content/api/generated/simpeg.simulation.BaseSimulation.html, https://docs.simpeg.xyz/latest/content/api/generated/simpeg.base.BasePDESimulation.html, https://docs.simpeg.xyz/latest/content/api/generated/simpeg.fields.Fields.html, https://docs.simpeg.xyz/latest/content/api/generated/simpeg.potential_fields.magnetics.Simulation3DIntegral.html, https://raw.githubusercontent.com/simpeg/simpeg/main/simpeg/simulation.py, https://raw.githubusercontent.com/simpeg/simpeg/main/simpeg/base/pde_simulation.py, https://raw.githubusercontent.com/simpeg/simpeg/main/simpeg/utils/solver_utils.py, https://raw.githubusercontent.com/simpeg/simpeg/main/simpeg/electromagnetics/static/resistivity/simulation.py, https://raw.githubusercontent.com/simpeg/simpeg/main/simpeg/potential_fields/magnetics/simulation.py, https://pymatsolver.readthedocs.io/en/latest/, https://raw.githubusercontent.com/simpeg/pymatsolver/main/pymatsolver/solvers.py, https://raw.githubusercontent.com/simpeg/pymatsolver/main/pymatsolver/wrappers.py, https://raw.githubusercontent.com/simpeg/pymatsolver/main/pymatsolver/direct/lu.py.

- Nouns. A `simulation` holds the `mesh` ("Mesh on which the forward problem is discretized"), the `survey` ("The survey for the simulation": sources and receivers), the `model` ("The inversion model"), the `solver` ("Numerical solver used to solve the forward problem. If None, an appropriate solver specific to the simulation class is set by default") and `solver_opts`.
- Solve and solution. `fields(m)` "Return the computed geophysical fields for the model provided" as a `Fields` object, "used to store the discrete field solution for a corresponding simulation object", indexed `f[:, 'e']` with shape `(n_edges, n_sources)`. `dpred(m, f=None)` "Predicted data for the model provided"; `f : simpeg.fields.Fields, optional — If provided, will be used to compute the predicted data without recalculating the fields`. `Jvec(m, v, f=None)` likewise. Both shapes: the field object, and data at receivers.
- Method choice, explained. `BasePDESimulation.__init__`: `if solver is None: solver = get_default_solver(); get_logger().info(f"Setting the default solver '{solver.__name__}' for the '{type(self).__name__}'...")`. Priority in `solver_utils.py`: "Pardiso (optional, but available on intel systems)", "Mumps (optional, but available for all systems)", "Scipy's SuperLU (available for all scipy systems)". The `solver` setter warns with a `PerformanceWarning` when given `SolverLU` or `Solver`: "might lead to high computation times. We recommend using a faster alternative such as 'pymatsolver.Pardiso' or 'pymatsolver.Mumps'."
- Reuse. DC resistivity `fields()`: `if self.Ainv is not None: self.Ainv.clean()`; `A = self.getA()`; `self.Ainv = self.solver(A, **self.solver_opts)`; `RHS = self.getRHS()`; `f[:, self._solutionType] = self.Ainv * RHS` — all sources in one solve, one RHS column each; `Jvec` reuses `self.Ainv`. Model-dependent caches are listed to be dropped: `_delete_on_model_update` returns `toDelete + ["_Jmatrix", "_gtgdiag"]`. Magnetics in integral form keeps the dense sensitivity `G` on first access (`if not hasattr(self, "_G")`) and computes `fields = G @ chi`; `store_sensitivities` is `'ram'`, `'disk'` (a `np.memmap` at `sensitivity_path`) or `'forward_only'`. Note the difference from MR: there the kept matrix is geometry only and χ is the model that changes; in MR χ sits inside the matrix.
- pymatsolver. "Solving Ax = b should be as easy as: Ainv = Solver(A); x = Ainv * b"; "All solvers work with scipy.sparse matricies, and a single or multiple right hand sides using numpy". `SolverLU.__init__`: `self.solver = splu(sp.csc_matrix(self.A), **self.kwargs)`; "The transposed solver (.T) re-uses this solver's LU factorization instead of factoring A.T"; `wrap_direct` docstring: "Scipy's spsolve does not support reuse, so we must pass factorize=false"; `Base.solve` with `check_accuracy=True` raises `SolverAccuracyError`: "Accuracy on solve is above tolerance: {resid_norm} > {tolerance}"; `clean()` releases the factorization.

### FEniCSx / dolfinx (finite elements on PETSc)

Sources: https://docs.fenicsproject.org/dolfinx/main/python/generated/dolfinx.fem.petsc.html, https://docs.fenicsproject.org/dolfinx/main/python/demos/demo_poisson.html, https://jsdokken.com/dolfinx-tutorial/chapter2/diffusion_code.html.

- Nouns. `msh = mesh.create_rectangle(...)`; `V = fem.functionspace(msh, ("Lagrange", 1))`; `bc = fem.dirichletbc(value=ScalarType(0), dofs=dofs, V=V)`; forms `a = ufl.inner(ufl.grad(u), ufl.grad(v)) * ufl.dx`, `L = ...`.
- Solve and solution. `LinearProblem(a, L, bcs=[bc], petsc_options={"ksp_type": "preonly", "pc_type": "lu", "ksp_error_if_not_converged": True}, petsc_options_prefix=...)` — "High-level class for solving linears problem using a PETSc KSP"; `uh = problem.solve()` returns a `fem.Function`; `solve()` "updates the solution u function(s) stored in the problem instance"; properties `A` "Left-hand side matrix", `b`, `solver` "The PETSc KSP solver", `u`. "The user is responsible for asserting convergence of the KSP solver e.g. problem.solver.getConvergedReason() > 0".
- Method choice: explicit through `petsc_options`; `"ksp_error_if_not_converged": True` makes a failure raise. Nothing automatic.
- Reuse. The problem object keeps `A`, `b` and the KSP; the `bcs` setter "rebuilds the cached dof markers, diagonal rows and per-block grouping that solve() reuses", while "Condition values are re-read on every solve". Time stepping (tutorial): "the matrix A does not change from one time step to another, thus we only need to assemble it once"; `A = assemble_matrix(bilinear_form, bcs=[bc]); A.assemble()`; `solver = PETSc.KSP().create(domain.comm); solver.setOperators(A)` once; per step `assemble_vector(b, linear_form); apply_lifting(...); set_bc(...); solver.solve(b, uh.x.petsc_vec)`.

### bempp-cl (boundary elements)

Sources: https://bempp.com/documentation/get_started.html, https://bempp.com/documentation/tutorials.html, https://raw.githubusercontent.com/bempp/bempp-cl/notebooks/laplace/laplace_interior_dirichlet.ipynb, https://raw.githubusercontent.com/bempp/bempp-cl/main/bempp_cl/api/assembly/boundary_operator.py, https://raw.githubusercontent.com/bempp/bempp-cl/main/bempp_cl/api/assembly/assembler.py, https://raw.githubusercontent.com/bempp/bempp-cl/main/bempp_cl/api/assembly/potential_operator.py, https://raw.githubusercontent.com/bempp/bempp-cl/main/bempp_cl/api/operators/boundary/laplace.py.

- Nouns. "Bempp solves discretised problems on grids (or meshes) of triangular cells": `grid = bempp_cl.api.shapes.sphere(h=0.1)`; `dp0_space = function_space(grid, "DP", 0)`, `p1_space = function_space(grid, "P", 1)`; operators `single_layer(domain, range_, dual_to_range, parameters=None, assembler="default_nonlocal", device_interface=None, precision=None)`; data as `GridFunction(p1_space, fun=dirichlet_data)`.
- Solve and solution. `rhs = (0.5 * identity + dlp) * dirichlet_fun`; `neumann_fun, info = bempp_cl.api.linalg.cg(slp, rhs, tol=1e-3)` (GMRES in the getting-started page). The solution is a `GridFunction`, a density on the surface, like MR's `ChargeSheet`. Field at points goes through potential operators: `slp_pot = operators.potential.laplace.single_layer(dp0_space, points)`, `dlp_pot = ...double_layer(p1_space, points)`, `u_evaluated = slp_pot * neumann_fun - dlp_pot * dirichlet_fun` ("We can now use Green's representation theorem to evaluate the solution on these points"); `PotentialOperator.evaluate` "Apply the potential operator to a grid function", with an `evaluation_points` property.
- Method choice. Assembler names: `"only_singular_part"`, `"only_diagonal_part"`, `"dense"`, `"default_nonlocal"`, `"sparse"`, `"fmm"`; `"default_nonlocal"` maps straight to `DenseAssembler`, not by problem size; FMM only on request and only with Exafmm installed ("No compatible FMM library found. Please install Exafmm"). The prior for MR's hierarchical matrices (#103): an option, silent default dense.
- Reuse. `BoundaryOperator.weak_form()`: "Return the weak form (assemble if necessary)", body `if not self._cached: self._cached = self._assemble()`; `strong_form()` multiplies by an inverse mass matrix cached on the space. The operator object is the cache; it is iterated, not factorized, in the pages read.
- Sweeps: none.

No reuse, no automatic choice.

### scipy: the reuse primitive

Sources: https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.factorized.html, https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.splu.html, https://docs.scipy.org/doc/scipy/reference/generated/scipy.linalg.lu_factor.html, https://docs.scipy.org/doc/scipy/reference/generated/scipy.linalg.lu_solve.html, https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.linalg.spsolve.html.

- `factorized(A)`: "Return a function for solving a sparse linear system, with A pre-factorized"; the returned `solve` "should be passed an ndarray of shape (N,)". A closure is the object.
- `splu(A, permc_spec=None, ...)`: "Compute the LU decomposition of a sparse, square matrix", returns a `SuperLU` object with a `solve` method (`B = splu(A); B.solve(x)`); SuperLU library; default column ordering COLAMD.
- `lu_factor(a, overwrite_a=False, check_finite=True)`: "Compute pivoted LU decomposition of a matrix", returns `lu` ("Matrix containing U in its upper triangle, and L in its lower triangle") and `piv` (0-based pivot indices), wrapping LAPACK `*GETRF`; `lu_solve((lu, piv), b, trans=0, overwrite_b=False, check_finite=True)` "solves an equation system, a @ x = b, given the LU factorization of a". Both accept batch dimensions. Neither page says anything about thread safety; MR #131 found `lu_solve` shifting the pivots in place during a call (brief, section 1), so a copy of `piv` per call is MR's own guard, not scipy's.
- `spsolve(A, b, permc_spec=None, use_umfpack=True)`: "if True (default) then use UMFPACK for the solution. This is only referenced if b is a vector and scikits.umfpack is installed" — an automatic choice that depends on what is installed and says nothing.

## Lessons for this plan, each with its source

1. **Keep two steps, and make the first step's object the unit of reuse: but reuse by holding the object, not by a store.** Every library hands the user the discretization (NGSolve `Mesh`/`H1`, scikit-fem `Basis`, FEniCSx `functionspace`, bempp `function_space`, SimPEG `simulation`) and the factorization as an object (`a.mat.Inverse`, `splu`, `factorized`, `pymatsolver.Solver(A)`, Radia `radRlxPre` handle, MagTense tensor). A global LRU keyed on a fingerprint has no prior among them. Sources: NGSolve unit-1.4 and 3.1, scipy `factorized`/`splu`, pymatsolver index and `direct/lu.py`, ESRF reference `radRlxPre`, MagTense `get_H_field`.
2. **Invalidate on the setters that change the matrix, and name them.** SimPEG `_delete_on_model_update` (`["_Jmatrix", "_gtgdiag"]` added by the DC simulation), `Ainv.clean()` before a new factorization; FEniCSx `bcs` setter rebuilding cached markers while "Condition values are re-read on every solve"; NGSolve preconditioner updated on re-assembly; bempp `_cached` weak form. For the plan's mesh object: the fingerprint (kept from #132) is the check, but the common practice is explicit invalidation on known setters, with the fingerprint as the safety net, not the only mechanism. Sources: SimPEG resistivity `simulation.py`, dolfinx `fem.petsc` page, NGSolve unit-2.1.1, bempp `boundary_operator.py`.
3. **Return a solution object with `getB`, and let observers be optional.** SimPEG `fields(m)` then `dpred(m, f=f)` "without recalculating the fields"; bempp density then potential operators at `points`; Radia objects then `radFld` anywhere; MagTense is the exception that needs `pts` at solve time. MR's `FemSolution` and `Solved` dataclass are the in-house shapes. For a path, B at observers passed in (MagTense's shape) is acceptable because it is the only shape that does not grow with the steps; for one configuration the object is the norm. Sources: SimPEG `simulation.py` docstrings, bempp Laplace notebook, Radia introduction, MagTense `run_simulation`, `fem/_solve.py:304-360`, `validation/methods.py:36-44`.
4. **An automatic choice must log what it chose and why, and be overridable; no library picks the discretization itself.** SimPEG logs "Setting the default solver ..." and warns on a slow manual choice; MR's `apply_demag` already logs "solver='auto' chose ...: FFT covers ...%". scipy `spsolve` and bempp `default_nonlocal` are the silent kind. Face charge against cells is a discretization choice, which no comparable makes for the user; its "observer inside" test has no prior at all. Sources: `pde_simulation.py`, `solver_utils.py`, `demag.py:1466-1470, 1603-1608`, scipy `spsolve`, bempp `assembler.py`.
5. **The narrow form of paths is "many right-hand sides on one factorization", which every library does as RHS columns or a user loop; memory handling is a visible knob.** SimPEG `Ainv * RHS` with one column per source and `store_sensitivities` `'ram'|'disk'|'forward_only'`; pymatsolver "single or multiple right hand sides"; scipy `lu_solve` batch dimensions; FEMM re-solving 16 positions. Chunks of ~100 steps are the plan's private matter; a documented memory mode is the public prior. Sources: SimPEG resistivity and magnetics `simulation.py`, pymatsolver index, scipy `lu_solve`, FEMM CoilGun.
6. **Report accuracy with the solution.** FEniCSx leaves convergence to the user but exposes `solver.getConvergedReason()`; pymatsolver's `check_accuracy` raises with the residual; Radia returns the last change in magnetization; MR's `FemSolution.seconds`/`ndof` and `face_charge_info` already carry size and time. A `study()` that reports an error estimate per rung is the natural next field. Sources: dolfinx `fem.petsc`, pymatsolver `solvers.py`, ESRF `radRlxAuto`, `fem/_solve.py:304-322`, `face_charge/_apply.py:115-118`.
7. **Refuse with a message that names the cause; it is normal practice.** SimPEG's `solver` setter type-checks and warns; pymatsolver raises on a non-square matrix and on accuracy; scipy `check_finite`; MR `apply_demag` on paths today. The plan's refusal "naming the part and how many matrices" is in line. Sources: `pde_simulation.py`, `solvers.py`, scipy `lu_factor`, `demag.py:1663-1668`.
8. **Iterative solvers keep the operator, not a factorization: Radia and MagTense relax on a kept interaction matrix or tensor.** Radia's `radRlxMan`/`radRlxAuto` take the matrix handle and can be called again; MagTense's `get_H_field` takes the precomputed tensor. For MR's method of moments under GMRES (no factorization, brief section 2), the comparable reuse is keeping the assembled operator (FFT blocks or dense T) on the mesh object. Sources: ESRF reference `radRlxPre/Man/Auto`, MagTense `get_demag_tensor`/`get_H_field`.
9. **Hierarchical or fast methods are options with a silent dense default, not an automatic switch by size.** bempp `"default_nonlocal"` resolves to dense; `"fmm"` must be asked for and needs Exafmm. A prior for #103. Source: bempp `assembler.py`.
10. **Names.** `solve` is the verb everywhere a solve happens in Python (scikit-fem `solve`, FEniCSx `problem.solve()`, bempp `linalg.cg/gmres`, Radia `rad.Solve`, NGSolve `solvers.CG`); `mesh` is a noun everywhere (NGSolve `Mesh`, scikit-fem `Mesh`, FEniCSx `mesh` module, SimPEG `mesh`, bempp `grid`). SimPEG's `simulation` is the one object that owns mesh, survey, solver and cached factorization together: the closest noun to what the plan's mesh object would become. MR's own `meshing` module and `mesh_*` functions (`validation/methods.py:19`, `docs/quickstart.md:113-120`) are the only collision found. Sources: the pages above, `meshing.py`.
